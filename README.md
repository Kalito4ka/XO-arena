# XO-arena

Курсовой проект по разработке серверной части веб-приложения «Крестики-нолики». В XO-arena можно играть вдвоём по ссылке или найти соперника через очередь.

## Возможности

| Режим | Правила | Время на ход |
| --- | --- | ---: |
| Классика | Поле 3 × 3, победа за три символа в ряд | 15 с |
| Ультимативный | Девять связанных полей, победа за три выигранных поля в ряд | 45 с |
| Пожирающий (Gobblers) | Фишки трёх размеров можно перемещать и накрывать более крупными | 30 с |

- Игра по приглашению доступна гостям и игрокам с аккаунтом.
- Онлайн-подбор ищет соперника в выбранном режиме и доступен после входа.
- Можно играть одну начатую партию в каждом режиме. Новая комната заменяет прежнее ожидание, сопернику даётся 3 минуты.
- После завершения партии у обоих участников есть 30 секунд, чтобы согласиться играть снова.
- Если время хода истекло, фоновый обработчик выполняет случайный допустимый ход.
- Профиль показывает текущие и последние 10 завершённых партий, а также статистику классики.
- На странице игры отображается топ-5. Общий рейтинг показывает до 25 игроков, завершивших минимум 10 партий суммарно во всех режимах. По умолчанию рейтинг отсортирован по победам. Также доступны количество партий и процент побед.

## Запуск с нуля

Нужен запущенный Docker Desktop с Docker Compose. Выполняйте команды в PowerShell из папки проекта, где лежит `compose.yaml`.

1. Если файла `.env` ещё нет, создайте его из шаблона и задайте пароль PostgreSQL.

   ```powershell
   Copy-Item .env.example .env
   ```

2. Запустите PostgreSQL и дождитесь его готовности.

   ```powershell
   docker compose up -d --wait db
   ```

3. Для **пустой базы** примените миграции `001`–`009` по порядку. Для существующей базы применяйте только ещё не выполненные миграции.

   ```powershell
   Get-ChildItem -Path .\database -Filter '*.sql' -File |
       Sort-Object Name |
       ForEach-Object {
           Get-Content -Raw -Encoding UTF8 -LiteralPath $_.FullName |
               docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
           if ($LASTEXITCODE -ne 0) {
               throw "Ошибка миграции $($_.Name)"
           }
       }
   ```

4. Запустите приложение и откройте [localhost:8080](http://localhost:8080). Если вы изменили `APP_PORT` в `.env`, используйте выбранный порт.

   ```powershell
   docker compose up --build -d
   docker compose ps
   ```

Остановить приложение с сохранением данных можно командой `docker compose down`.

## Как устроен проект

- `client/` — страницы игр, лидеров и профиля на HTML, CSS и JavaScript.
- `server/` — PHP API под Apache, правила игр и фоновый обработчик таймеров.
- `database/` — SQL-миграции для PostgreSQL.
- `nginx/` — настройка Nginx, который отдаёт страницы и передаёт запросы `/api/` серверу PHP.

### Архитектура

Приложение использует разделение обязанностей по MVC с сервисным слоем.
Представление находится в `client/`, контроллеры — в `server/src/Http/`,
а модель состоит из сущностей, игровых правил и сервисов. Контроллеры
вызывают сервисы и возвращают JSON для клиентского представления.

- `server/src/Entity/` — сущности, соответствующие четырём таблицам БД:
  `User` (пользователь), `Game` (сохранённая партия), `UserStats` (статистика
  пользователя в режиме), `MatchmakingEntry` (заявка на подбор соперника).
  Они содержат типизированные данные и не выполняют SQL-запросы.
- `server/src/Repository/` — загрузка и сохранение сущностей через PDO.
  Репозитории преобразуют строки БД в объекты; SQL находится в этом слое.
- `server/src/Service/` — регистрация, вход, создание партий, ходы, подбор,
  повторная игра и учёт результатов. Сервисы управляют общими транзакциями,
  передавая репозиториям одно подключение к БД.
- `server/src/Game/` — правила классики, Ultimate и Gobblers. Эти классы
  отвечают за допустимость ходов и исход игры, а `Entity/Game` — за данные
  сохранённой партии и её участников.

История и таблица лидеров — выборки с объединением и агрегированием данных,
поэтому отдельные хранимые сущности для них не создаются. Сущности неизменяемы:
после сохранения репозиторий возвращает новый объект с актуальными данными.
Хеши паролей и гостевые ключи закрыты; сервисы явно формируют публичные ответы.

## Проверка

Проверки правил и восстановления состояния из базы:

```powershell
docker compose exec server php src/Tests/ClassicGameTest.php
docker compose exec server php src/Tests/UltimateGameTest.php
docker compose exec server php src/Tests/GobblersGameTest.php
docker compose exec server php src/Tests/UltimatePersistenceTest.php
docker compose exec server php src/Tests/GameRoomsTest.php
docker compose exec server php src/Tests/EntityPersistenceTest.php
```

`GameRoomsTest.php` проверяет регистрацию, ограничения комнат, повторную игру и рейтинг в отдельной временной схеме PostgreSQL, затем удаляет её.

`EntityPersistenceTest.php` проверяет восстановление сущностей из БД,
сохранность истории ходов трёх режимов, откат транзакций, авторизацию
и подбор соперника. Проверка также использует отдельную временную схему.

Для проверки в браузере войдите в два разных аккаунта в отдельных браузерах. Создайте партию по ссылке и сделайте ход. Затем выберите один режим в обоих браузерах и нажмите «Найти соперника». Должна открыться общая партия. В Gobblers дождитесь истечения 30 секунд без хода и проверьте, что сервер сделал ход автоматически. После завершения партии откройте историю в профиле.

Свежие логи API и таймеров:

```powershell
docker compose logs --since 2m server worker
```
